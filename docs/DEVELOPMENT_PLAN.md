## 高度な分析の準備トラック

- Status: `IN PROGRESS`
- 対応する元Phase: Phase 5.5、Phase 6、Phase 7を土台とし、将来のAI説明はPhase 10、将来のHealth/スマートウォッチ項目はPhase 9の完了後に段階接続する。元Phase番号を置換しない。
- 目的: 利用可能な本人記録を横断して傾向を再現可能に確認できる「高度な分析」を、詳細分析と分離して段階的に実装する。
- 現在の実装: メニューの「詳細分析」は`/analysis`、同階層の「高度な分析」は`/advanced-analysis`へ直接遷移する。後者には睡眠×体調の条件再分析、関連分析、データ品質・根拠の入口があり、AI総合分析、時刻別気象×頭痛、固定テーマ、外部AI通信は未実装として表示する。`CONFIRMED`
- 初期画面方針: トップはAI総合分析のメインカード、利用可能な項目だけの個別分析入口、条件を変えて調べる入口の順に置く。総合分析で対象を最初に選ばせず、十分な根拠がない場合は分析不能な理由を示す。未実装の運動・食事・Health値を利用可能な機能として表示しない。
- 詳細画面方針: 総合・個別ともに、原則として「結果 → グラフ → 根拠」の順に表示する。根拠には期間、使用項目、比較できた記録数、欠損、日時対応、計算方法、解釈上の限界を含める。グラフ形式は分析内容に合わせて選び、一律に固定しない。
- 複数条件方針: 条件は追加・削除・変更でき、「再分析」で計算結果・グラフ・説明を更新する。AIが見つけた傾向から開く場合は対応条件を初期値として引き継ぐ。条件を絞った比較対象と基準比較対象の両方を明示し、比較数不足では結論を出さない。
- 固定テーマ方針: ユーザーは個別の分析テーマを固定できる。固定対象は計算結果ではなくテーマであり、期間や記録が変われば結果・グラフ・説明を更新する。データ不足でも別テーマへ自動置換しない。総合分析メインカードは固定テーマとは別に常にトップへ置く。
- 分析・説明の境界: 計算エンジンが使用項目、対象期間、件数、欠損、日時対応、統計値を確定し、AIは確定した結果と限界の説明だけを担当する。AIに統計値・存在しない記録・因果関係を創作させない。
- 未決定項目: 統計手法、最低件数、判定閾値、条件探索の多重比較対策、固定テーマの保存責務、AI実行場所・送信範囲・費用・会話履歴。これらは実装前に別の承認単位で決定する。
- このトラックでは実装しないもの: 運動・食事の正式保存、Health/スマートウォッチ同期、外部AI接続、医学的診断・因果推論・健康点、データ不足時の推測。
- Definition of Done（初回本実装前の設計完了）: 対象データ、品質条件、日時対応、再分析条件、固定テーマ、計算結果とAI説明の契約、画面ごとのデータ不足表示、テストfixtureが承認済み文書で固定される。
- 必須テスト（将来の実装単位）: サンプル除外、0と欠損、少数・全同値・外れ値、同日/翌日対応、条件追加/削除/変更、データ不足、テーマ固定、再分析、既存分析との一致。
- 次Phaseへの移行条件: 初期分析対象と品質ゲートを承認し、Phase 5.5〜7の既存計算を壊さない小単位の実装計画がある。
- 未確認事項・差分: C-11、C-13、C-14、C-15。
