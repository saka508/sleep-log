# Sleep Log 正式開発基準

この文書は、現在のSleep Logに対する正式な開発基準を記録する。Phase番号は過去の実装順ではなく、今後必要となる機能分類を表す。

## 現在の基準状態

- 基準コミット: `56d391adbc860781c7e1359c3aa341d4455937b3`
- `main` と `origin/main` は一致
- GitHub Actions #17 成功、GitHub Pages公開成功
- `/sleep-log/` と `/sleep-log/analysis` は公開確認済み
- `AGENTS.md` は既存の未追跡ファイルであり、変更・削除・コミットしない

既存のPWA、睡眠記録、昼寝、カフェイン、頭痛、天候・気圧、分析、CSV互換性を再実装しない。作業開始時は必ず現在のコードと本基準を照合し、機能を「完了／一部実装／未実装／検証不足／将来対応」に分類する。

## 保存形式と互換性

- 既存のAsyncStorageキー、`SleepRecord`、CSV列順を正本として維持する。
- 現在の`DailyConditionRecord`は旧`SleepRecord`から生成する読み取りモデルで、`schemaVersion: 1`を持つ。
- 保存形式全体を`DailyCondition`へ移行したわけではなく、現時点でmigrationは実施しない。
- 未入力と0を区別し、欠損値を分析で0に補正しない。
- データ構造を変更する場合は、バージョンごとに分離した冪等なmigrationとバックアップ・復元確認を先に設計する。読み込み成功前に旧データを削除しない。
- 日付は端末のローカル日付を使い、UTC変換で日付境界をずらさない。日をまたぐ睡眠の割当、深夜、DST、重複日付、`createdAt`/`updatedAt`形式をコード・テスト・文書で明確にする。

## 将来のデータ設計

1日を基本単位とするが、運動、睡眠セッション、食事、カフェイン等は必要に応じてイベント配列にする。複数回発生するイベントには安定した`id`、時刻、単位、`source`を持たせる。

手入力・ウェアラブル・Health系API・外部APIの値が競合した場合は無条件に上書きしない。手入力値を保護し、自動取得値にはprovider、取得日時、観測日時を保持できる型と責務を先に確保する。現段階で複雑な同期処理は実装しない。

## 分析・提案

- 同日データと翌日データを明確に区別する。
- 期間、記録数、欠損除外後のサンプル数、計算方法、最低必要数、分析ロジック版を管理または表示する。
- 相関は関連の目安として表現し、因果・診断・治療を断定しない。
- 少数・偏り・同一値だけのデータから強い提案を出さない。
- 本人データだけを根拠に睡眠時間を短くする提案を自動生成しない。
- 固定的な安全条件と本人データによる個人化を分離する。

## PWA・安全性

- オフラインで既存記録を閲覧・保存できる状態を維持する。
- 外部API失敗時も手入力を保存できるようにする。
- Service Worker更新で保存データを削除しない。古いキャッシュから復旧できる手順を保つ。
- GitHub Pagesの`/sleep-log/`サブパスを壊さない。
- 健康・位置情報を無断送信せず、APIキーや秘密情報をフロントエンド・Gitへ出さない。
- Health連携は各プラットフォーム公式仕様を確認してから実装し、実現できない連携を動作するものとして扱わない。
- ChatGPT等への共有は、ユーザーが期間と内容を明示して書き出す方式を基本とし、自動同期を有効化しない。

## 各作業単位の完了条件

開始時に`git status`、`git log -1`、`main`と`origin/main`の差分、最新Actions、既知の失敗を確認する。変更は小さく保ち、typecheck、lint、test、build、PWA、既存データ互換性を確認してからcommit・pushする。未検証の変更を正常な`main`へ混ぜない。
