## ADR-20260914-004：既存データ・CSV・日時・PWA公開契約を保護する

## ADR-20260914-005：各モードの視覚的方向性を分ける

- Status: ACCEPTED
- 日付: 2026-09-14
- 決定内容: Sleep Logは森林・自然・空・水面・葉を使う実用優先のライト表現、運動モードは黒・シルバー・工業的/金属的表現、集中モードは黒背景・赤い光・ホログラム/鉄の心臓・パルス表現を基本方向とする。赤は運動モードではアクセントに限定する。
- 決定理由: 睡眠・回復と運動・集中の用途を視覚的に区別しつつ、各画面の情報優先度を保つため。
- 影響するPhase／機能: UX-A、UX-B、UX-C、Phase 3、4。
- 以前の仕様との差分: 初期の運動モード案にあった赤主体を、黒・シルバー主体で赤アクセントへ整理した。
- 確認根拠: ユーザーが承認した森林ホーム方針と、2026-09-14の明示されたモード方向性。

## ADR-20260914-006：天候円の記録導線と更新操作を分離する

- Status: ACCEPTED
- 日付: 2026-09-14
- 決定内容: 天候円本体のタップは頭痛イベント記録へ進む。「天候を更新」は入力画面へ遷移せず、ホーム内の天気・気温・気圧・取得時刻と状態表示だけを更新する。失敗時は表示中の保存済み値を消さない。
- 決定理由: 頭痛発生時の導線と天候更新を混同せず、現在情報をホームで確認できるようにするため。
- 影響するPhase／機能: Phase 1、3、4、UX-A、天候・頭痛イベント。
- 以前の仕様との差分: 以前の「天候を更新」で記録画面を開く挙動を廃止した。
- 確認根拠: ユーザーの明示決定、commit `a5577c3`、`app/(tabs)/index.tsx`、`tests/home-weather.test.ts`。

## ADR-20260914-007：AI・Health・予測を実装済みとして扱わない

- Status: ACCEPTED
- 日付: 2026-09-14
- 決定内容: AI通信、Health/スマートウォッチ同期、眠気・コンディション・翌日予測は、追跡済み実装と安全条件が揃うまで実装済みと表記しない。データ不足時に予測・提案を出さず、医療診断や因果断定をしない。
- 決定理由: 架空の測定値・提案、無断外部送信、健康情報の過度な断定を防ぐため。
- 影響するPhase／機能: Phase 7〜10、ホームAIカード、集中モード心拍表示。
- 以前の仕様との差分: 将来構想と現在機能を明確に分離した。
- 確認根拠: 2026-09-14のユーザー明示指示、現在のAIプレースホルダー、追跡済みコードにHealth adapterがないこと。

## ADR-20260919-001：時刻別気圧は短期・独立履歴として扱う

- Status: ACCEPTED
- 日付: 2026-09-19
- 決定内容: Open-Meteoの`surface_pressure`時刻別系列は、日次`SleepRecord`とCSVを変更せず、独立AsyncStorageキー`sleep-log.pressure-history.v1`へバッチ単位で保存する。各バッチは座標・住所・地点再識別子を持たず、取得時刻から30日、最大100バッチまで保持する。地点変更は識別・統合せず、バッチ間の気圧変化やグラフ接続を行わない。
- 決定理由: 頭痛イベント等と時刻単位で照合できる余地を残しつつ、位置情報の常時保存、日次記録への大量重複、地点をまたぐ不正確な比較を避けるため。
- 影響するPhase／機能: Phase 1、Phase 3、Phase 5、天候円、頭痛イベント、バックアップ。
- 以前の仕様との差分: 日次天候スナップショットのみだった気圧保持に、期限・容量付きの時刻別履歴を追加する。既存保存キーとCSV列順は変更しない。
- 確認根拠: 2026-09-19のユーザー承認、`lib/pressure-history.ts`、`lib/pressure-history-store.tsx`。

## ADR-20260919-002：気圧履歴の更新・頭痛関連・復元の境界

- Status: ACCEPTED
- 日付: 2026-09-19
- 決定内容: 手動「天候を更新」と頭痛イベント画面で天候を取得した時に時刻別気圧バッチを作る。前景表示中は、位置情報が既に許可され、前回取得からおよそ1時間経過した場合だけ起動・復帰・時間経過を契機に更新を試みる。PWAのバックグラウンド定期実行は保証しない。頭痛イベントは同時に作成できたバッチIDだけを任意関連として持ち、既存日次頭痛を変換しない。履歴は既存CSVと別の専用JSONで復元する。
- 決定理由: 権限を尊重し、バックグラウンド追跡をしないまま、取得済みデータの重複を抑え、時刻別照合の出所を保つため。
- 影響するPhase／機能: Phase 1、Phase 3、Phase 5、PWA、頭痛イベント、バックアップ。
- 以前の仕様との差分: 天候の現在値だけを手動取得する方針から、許可済みの前景限定更新と独立JSON復元を追加する。
- 確認根拠: 2026-09-19のユーザー承認、`app/(tabs)/index.tsx`、`app/headache-event.tsx`、`lib/pressure-history-backup-service.ts`。

## ADR-20260920-001：詳細分析と高度な分析を並列に分離する

- Status: ACCEPTED
- 日付: 2026-09-20
- 決定内容: 詳細分析は睡眠・体調・頭痛・環境など個々の項目の記録、推移、集計、短い分析を確認する画面とする。高度な分析は利用可能な本人記録を横断する本格的な傾向分析とし、詳細分析を経由せずメニューから直接開く。現在の`/advanced-analysis`は準備中トップのみであり、本体機能は未実装として扱う。
- 決定内容: 高度な分析トップは、AI総合分析のメインカード、利用可能な項目だけを使う個別分析入口、条件を変えて調べる入口の順に構成する。詳細画面は原則「結果 → グラフ → 根拠」の順とし、根拠には期間、使用項目、比較数、欠損、日時対応、計算方法、限界を示す。個別テーマは固定できるが、固定対象は結果ではなくテーマとする。
- 決定内容: 計算エンジンが記録・日時対応・対象数・欠損・統計値を確定し、AIは確定した結果と限界を説明する。根拠不足時は傾向を創作せず、分析できない理由を示す。複数条件の探索結果を因果関係や確定的な本人傾向として扱わない。
- 決定理由: 個別の振り返りと長期・横断的な傾向発見を混同せず、利用できないデータやAI機能を完成済みと誤認させないため。また、ユーザーが条件を変えて傾向を検証できる構成を、計算の再現性と説明可能性を保ったまま導入するため。
- 影響するPhase／機能: Phase 5.5、6、7、10、分析画面、メニュー、AIプレースホルダー、将来の運動・栄養・Health連携。
- 以前の仕様との差分: 既存の詳細分析だけを分析入口としていた状態から、高度な分析への並列導線と準備中トップを追加する。運動・食事・Health/スマートウォッチ・AI通信を実装済みとして扱わない方針は維持する。
- 確認根拠: 2026-09-20のユーザー明示指示、commit `1c50dd1`、`app/menu.tsx`、`app/advanced-analysis.tsx`、公開Web版の導線確認。
