## ADR-20260914-003：UIと演出をUX横断トラックとして管理する

- 決定内容: Sleep Log静的UIをUX-A、運動・集中モード静的UIをUX-B、モーション・アニメーション・効果音をUX-Cとして、対応する機能Phaseへ横断接続する。

## ADR-20260914-004：既存データ・CSV・日時・PWA公開契約を保護する

- Status: ACCEPTED
- 日付: 2026-09-14
- 決定内容: 既存AsyncStorageキー、`SleepRecord`、独立頭痛イベント、CSV列順、ローカル日付・既存時刻形式、PWA manifest、Service Worker、GitHub Pagesの`/sleep-log/`公開パスを無断で破壊変更しない。migrationが必要なら実装前にversion、冪等性、backup、復旧、旧データテストを設計し、ユーザー確認を得る。
- 決定理由: 個人の健康・生活記録の消失と、既存Android/PWA利用者の互換性破壊を避けるため。
- 影響するPhase／機能: Phase 1〜10、import/export、公開・配布。
- 以前の仕様との差分: なし。過去の互換性方針を正本へ固定した。
- 確認根拠: 継続したユーザー指示、`sleep-log.local-data.v1`、`sleep-log.headache-events.v1`、`lib/csv-core.ts`、`app.config.ts`、`public/sw.js`。

## ADR-20260914-005：各モードの視覚的方向性を分ける

- Status: ACCEPTED
- 日付: 2026-09-14
- 決定内容: Sleep Logは森林・自然・空・水面・葉を使う実用優先のライト表現、運動モードは黒・シルバー・工業的/金属的表現、集中モードは黒背景・赤い光・ホログラム/鉄の心臓・パルス表現を基本方向とする。赤は運動モードではアクセントに限定する。
- 決定理由: 睡眠・回復と運動・集中の用途を視覚的に区別しつつ、各画面の情報優先度を保つため。
- 影響するPhase／機能: UX-A、UX-B、UX-C、Phase 3、4。
- 以前の仕様との差分: 初期の運動モード案にあった赤主体を、黒・シルバー主体で赤アクセントへ整理した。
- 確認根拠: ユーザーが承認した森林ホーム方針と、2026-09-14の明示されたモード方向性。

## ADR-20260914-006：天候円の記録導線と更新操作を分離する

- Status: ACCEPTED
- 日付: 2026-09-14
- 決定内容: 天候円本体のタップは頭痛イベント記録へ進む。「天候を更新」は入力画面へ遷移せず、ホーム内の天気・気温・気圧・取得時刻と状態表示だけを更新する。失敗時は表示中の保存済み値を消さない。
- 決定理由: 頭痛発生時の導線と天候更新を混同せず、現在情報をホームで確認できるようにするため。
- 影響するPhase／機能: Phase 1、3、4、UX-A、天候・頭痛イベント。
- 以前の仕様との差分: 以前の「天候を更新」で記録画面を開く挙動を廃止した。
- 確認根拠: ユーザーの明示決定、commit `a5577c3`、`app/(tabs)/index.tsx`、`tests/home-weather.test.ts`。

## ADR-20260914-007：AI・Health・予測を実装済みとして扱わない

- Status: ACCEPTED
- 日付: 2026-09-14
- 決定内容: AI通信、Health/スマートウォッチ同期、眠気・コンディション・翌日予測は、追跡済み実装と安全条件が揃うまで実装済みと表記しない。データ不足時に予測・提案を出さず、医療診断や因果断定をしない。
- 決定理由: 架空の測定値・提案、無断外部送信、健康情報の過度な断定を防ぐため。
- 影響するPhase／機能: Phase 7〜10、ホームAIカード、集中モード心拍表示。
- 以前の仕様との差分: 将来構想と現在機能を明確に分離した。
- 確認根拠: 2026-09-14のユーザー明示指示、現在のAIプレースホルダー、追跡済みコードにHealth adapterがないこと。

## ADR-20260914-008：日次頭痛と独立頭痛イベントを併存させる

- Status: ACCEPTED
- 日付: 2026-09-14
- 決定内容: 既存`SleepRecord`の日次頭痛を削除・置換・自動変換せず、複数回記録できる`HeadacheEvent`を専用キーへ保存する。両者を分析する場合はデータソースと対象範囲を明示し、無言で二重集計しない。
- 決定理由: 既存データ互換性を保ちながら、発生時刻とその時点の天候を記録するため。
- 影響するPhase／機能: Phase 1、3〜5.5、頭痛、バックアップ、分析。
- 以前の仕様との差分: 1日1件の日次頭痛に加え、同日に複数の独立イベントを持てるようになった。
- 確認根拠: ユーザーの明示決定、commit `b546f6a`、`lib/headache-events.ts`、`lib/headache-store.tsx`、頭痛イベントテスト。
